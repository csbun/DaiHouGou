# 大口九：摄像头检测区域设计

## 背景

大口九目前对摄像头取得的完整画面执行人员检测和物体检测。家庭摄像头常会覆盖门外、窗户、
电视或其他不属于目标活动范围的区域，这些内容会增加无效检测，也可能触发不需要的状态变化或
物体播报。

本功能允许用户为每个摄像头划定一个矩形检测区域。区域是摄像头级配置，由该摄像头的全部视觉
规则共享。系统不跟踪摄像头移动，也不在画面变化后尝试重新匹配区域。

## 目标

1. 每个已保存摄像头拥有一个持久化矩形检测区域。
2. 用户在独立页面查看按需静态快照，并通过拖拽或百分比输入编辑区域。
3. 区域在缩放、补边、场景变化判断和模型推理之前应用。
4. 保存区域后只重启目标摄像头，其他摄像头和共享检测器继续运行。
5. 从数据库 schema v2 原地迁移到 v3，不改变已有摄像头的检测范围。
6. 不持久化、缓存或记录摄像头快照。

## 非目标

- 不支持多边形、多个矩形、排除区域或逐规则区域。
- 不做目标跟踪、摄像头移动检测、画面特征匹配或区域自动校正。
- 不提供实时视频、MJPEG 或 WebRTC 预览。
- 不保留历史快照，不允许用历史图片编辑离线摄像头。
- 不为区域修改增加配置审计事件或首页历史记录。
- 不改变现有模型、类别、置信度、场景变化阈值或欢迎规则状态机。

## 区域模型

新增不可变的 `DetectionRegion` 值对象：

```python
@dataclass(frozen=True)
class DetectionRegion:
    x: float
    y: float
    width: float
    height: float
```

坐标以摄像头解码后的原始画面为基准，左上角为原点，四个值均为归一化比例。有效区域满足：

- 所有值必须是有限数值；
- `x >= 0` 且 `y >= 0`；
- `width >= 0.02` 且 `height >= 0.02`；
- `x + width <= 1` 且 `y + height <= 1`；
- 输入在构造时保留六位小数，然后按以上约束校验。

全画面使用显式值 `(0, 0, 1, 1)`，不使用 `NULL` 表示。摄像头分辨率、宽高比、方向或机位
变化后，系统继续把相同归一化坐标应用到新画面，不使配置失效，也不尝试重新定位。

## 数据存储与迁移

SQLite schema 版本从 2 升级到 3。`cameras` 表新增四个非空实数字段：

```text
region_x       REAL NOT NULL DEFAULT 0
region_y       REAL NOT NULL DEFAULT 0
region_width   REAL NOT NULL DEFAULT 1
region_height  REAL NOT NULL DEFAULT 1
```

应用启动时支持以下两条路径：

1. 空数据库直接创建 schema v3。
2. 表集合正确的 schema v2 在同一事务内新增四列、把版本更新为 3，并保留摄像头、规则、全局
   配置和事件。

其他版本或表集合不匹配时，继续抛出 `IncompatibleSchemaError`。迁移后已有摄像头均为全画面；
新发现摄像头也使用全画面默认值。

`CameraConfig` 增加 `detection_region: DetectionRegion`。存储边界提供读取随摄像头配置返回、
以及 `set_camera_detection_region(camera_id, region)` 两个能力。未知摄像头抛 `KeyError`，非法区域
在进入存储前已经由值对象拒绝。多个页面同时保存同一摄像头时采用最后写入者生效，不做版本冲突
检测。

## 检测数据流

区域在 FFmpeg 滤镜链的最前端应用：

```text
RTSP 解码画面
    -> crop(归一化 ROI)
    -> fps
    -> 等比缩放
    -> 补边到 256x256 或 416x416
    -> CameraRuntime
       +-> 人员检测 -> PresenceTracker -> 欢迎规则
       +-> ROI 场景变化判断 -> 物体检测 -> 物体播报规则
```

全画面区域省略 `crop` 滤镜，保持现有 FFmpeg 命令和像素结果。非全画面区域使用原始输入宽高计算
裁剪参数，再执行现有的缩放和补边。人员模型、物体模型和 `SceneChangeGate` 只能看到裁剪后的
画面。

ROI 被视为新的完整检测画面：跨越边界的人员或物体会被截断，是否识别取决于区域内剩余内容；
物体框面积比例也相对 ROI 计算。特别地，大幅书本的 50% 排除阈值改为相对 ROI，而不是相对原始
全图。不增加中心点、相交比例或边界补偿规则。

## 运行时更新

`Runtime` 增加 `set_camera_detection_region(camera_id, region)`。调用在现有运行时锁内完成：

1. 把区域写入数据库；
2. 重新计算该摄像头的运行描述符；
3. 如果至少一条视觉规则开启且区域确实变化，停止并重建该摄像头的 `CameraRuntime` 和 FFmpeg
   取帧源；
4. 共享检测器、音箱工作线程和其他摄像头不重启。

运行描述符从 `(rule_ids, frame_size)` 扩展为 `(rule_ids, frame_size, detection_region)`。规则全部
关闭时只保存区域，不启动取帧或模型。区域未变化时不重启。

配置操作本身不得触发播报。ROI 更新造成的重启中，人员状态机按现有 `unknown` 基线启动，不把
画面中已有人员视为新进入；物体场景门控只把第一帧记录为参考帧，不在该帧执行物体模型。这个
抑制只消费一次：服务启动、首次开启物体规则、摄像头断线恢复，以及之后真正的场景变化仍保持
现有首帧或变化检测语义。

数据库写入成功后不因摄像头暂时无法恢复而回滚。摄像头按现有状态机制显示降级并继续重连，
保存接口仍报告配置已经持久化。

## 静态快照

区域编辑使用独立的一次性快照捕获能力，不复用检测帧源，因为检测帧已经裁剪，无法用于扩大
区域。即使摄像头规则全部关闭，用户也可以在进入编辑页时临时建立 RTSP 连接取一帧；捕获完成
后立即结束 FFmpeg 进程。

快照遵循以下约束：

- 始终包含未经 ROI 裁剪的完整解码画面；
- 保持宽高比，最长边不超过 1280 像素；
- 输出 JPEG，目标质量约 85；
- 只存在于捕获进程、服务内存和当前浏览器页面；
- 响应设置 `Cache-Control: no-store`，不写文件、数据库、事件或日志；
- 捕获超时、解码失败或空输出统一映射为可重试的快照不可用状态。

浏览器通过带现有 CSRF 令牌和同源校验的 `POST` 请求获取 JPEG，避免第三方页面利用图片 GET
反复触发摄像头连接。运行时验证摄像头已经保存在数据库中；未知摄像头返回 404，捕获失败返回
503。捕获不持有全局运行时配置锁，避免慢摄像头阻塞规则开关或其他配置保存；服务端串行化并发
快照捕获以限制额外解码负载。

## Web 页面与交互

首页摄像头行新增“检测区域”入口。全画面时不显示额外状态；非全画面时只显示简短的“已划定”，
不在首页放置坐标、图片或编辑控件。

区域编辑位于独立页面，通过查询参数传递可 URL 编码的摄像头 ID，以兼容包含空格、斜杠或其他
字符的流名称。页面显示摄像头名称、返回摄像头列表入口、预览区、四个百分比输入和以下命令：

- 刷新画面；
- 恢复全画面；
- 取消；
- 保存。

进入页面后自动捕获一次快照，之后不轮询，只在用户点击刷新时重新捕获。刷新仅替换背景图片，
保留当前归一化草稿和覆盖框。编辑期间运行中的检测继续使用已保存区域。

单矩形编辑器支持：

- 在空白处拖动以重新划定矩形；
- 拖动矩形主体进行移动；
- 使用四个角和四条边的控制点缩放；
- 鼠标和触摸指针事件；
- `X`、`Y`、`宽`、`高` 百分比输入，显示两位小数；
- 画布拖动始终把矩形限制在画面内。

手工输入不自动修正。非数字、非有限值、宽高不足 2% 或越界时，页面就地显示错误并禁用保存；
服务端使用相同规则再次校验。隐藏提交字段保留六位小数，避免只显示两位小数导致未编辑值失真。

“恢复全画面”只修改草稿，仍需点击保存。保存成功后停留在编辑页、更新已保存基线并显示结果；
“取消”返回首页。刷新、返回、浏览器刷新或关闭页面时，未保存草稿直接丢弃，不弹出确认。

## 离线与错误状态

无法取得快照时，页面仍显示已经保存的百分比坐标和重新获取操作，但禁用画面拖拽、普通坐标
编辑和普通保存。不使用历史图片兜底。

首次捕获或手动刷新失败后，页面清除当前预览图片；刷新前的图片不能继续用于编辑。当前草稿数值
可以保留显示，但保持锁定，直到取得新快照或用户选择恢复全画面。

离线状态下允许“恢复全画面”：点击后产生精确的 `(0, 0, 1, 1)` 草稿，并允许保存。其他任何
区域都不能在没有当前快照时盲改。

保存成功但摄像头尚未恢复时，页面区分显示“区域已保存”和摄像头运行状态；不把运行时恢复失败
误报为配置保存失败。未知摄像头、非法区域、CSRF 失败和快照不可用保持不同 HTTP 状态与页面
反馈。

## 安全与隐私

- 所有修改和快照捕获请求复用现有 Origin、CSRF cookie 和表单令牌校验。
- 摄像头 ID 只作为经过框架解析的表单或查询参数，不拼接到文件路径或 shell 命令。
- FFmpeg 通过参数数组启动，不经过 shell；ROI 只由已校验并格式化的有限浮点数生成。
- 页面和 JPEG 响应均禁止缓存。
- 错误消息不包含 RTSP URL、凭据、JPEG 内容或原始 FFmpeg 输出。
- 区域坐标不写入运行事件；应用日志只记录稳定错误类别和摄像头 ID。

## 测试策略

### 区域值对象与存储

- 接受全画面和边界内最小区域；
- 拒绝 NaN、无穷、负值、宽高不足 2% 和越界区域；
- 验证六位小数归一化；
- 验证空库创建 v3、v2 原地迁移、数据保留和默认全画面；
- 验证逐摄像头保存、最后写入生效和未知摄像头错误；
- 验证其他版本及异常表集合仍被拒绝。

### FFmpeg 与运行时

- 验证非全画面滤镜顺序为 `crop -> fps -> scale -> pad`；
- 验证全画面命令保持无 `crop`；
- 用生成视频验证 ROI 外变化不进入场景门控、ROI 内变化进入检测；
- 验证运行描述符包含区域，更新只重启目标摄像头；
- 验证规则关闭时保存不创建取帧源；
- 验证 ROI 更新后的物体第一帧只建立基线，后续变化正常检测；
- 验证正常启动、规则开启和断线恢复仍保留原有行为。

### 快照与 Web

- 验证一次性 FFmpeg 捕获保持宽高比、限制最长边并输出 JPEG；
- 验证超时、空输出和进程失败不会留下子进程或敏感错误；
- 验证区域页兼容包含空格和斜杠的摄像头 ID；
- 验证快照与保存请求的同源、CSRF、404、422 和 503 行为；
- 验证 JPEG 和 HTML 均带 `no-store`；
- 验证首页只显示入口及非全画面状态；
- 使用浏览器测试桌面和移动视口下的拖画、移动、八向缩放、触摸等价指针、刷新保留草稿、
  非法输入、离线全画面恢复及保存后停留页面。

## 验收标准

1. 用户能从任意摄像头行进入独立页面，并在当前完整快照上保存一个矩形区域。
2. 保存后只有该摄像头短暂重启，后续人员和物体检测只接收区域内画面。
3. 区域外画面变化不会触发该摄像头的物体场景变化检测。
4. ROI 保存本身不产生欢迎或物体播报。
5. 规则关闭、摄像头离线、快照失败和特殊字符摄像头 ID 均有确定行为。
6. 从 schema v2 升级后已有数据保留，所有摄像头仍默认检测全画面。
7. 服务端、浏览器缓存、数据库、事件和日志中均不持久化快照。
