# 家庭儿童陪护 MVP：人员进入欢迎规则设计

## 状态

已批准。本文定义设备兼容性 PoC 之后的首个 MVP，不替代
`docs/poc-runbook.md` 中的现场设备验证流程。

## 目标

在当前低配置局域网服务器上运行一个可长期驻留的应用，从 go2rtc 的 `xiaobai` 码流中检测
画面是否从“无人”变为“有人”。当内置欢迎规则开启时，应用从固定欢迎语中随机选择一句，
通过已验证的小米小爱音箱 Play 增强版直连路径播报。局域网管理页只提供规则开关，同时显示
必要的运行状态和最近一次触发结果。

MVP 的核心成功标准是证明以下链路能够无人值守运行：

```text
xiaobai -> go2rtc -> FFmpeg 取帧 -> 本地人员检测 -> 进入状态机
         -> 内置规则 -> 异步播报队列 -> MiService -> L05C 音箱
```

## 已确认的现场基线

- 当前只使用名为 `xiaobai` 的一路低码率码流。
- go2rtc 已能从实际摄像头拉取并转发视频。
- MiService 已能通过 MIoT `siid=5`、`aiid=3` 让实际 L05C 音箱播报。
- 压力和长期稳定性测试尚未执行；这不阻塞 MVP 开发，但仍是后续上线门槛。
- 当前服务器为 Intel Core i3-3217U、4 GB 内存、Intel HD Graphics 4000 和修改版 Debian。

## 范围

MVP 包含：

- 一个常驻应用进程和一个浏览器管理页。
- `welcome_on_person_entry` 一条内置规则。
- 规则的开启和关闭。
- 本地 CPU 人员检测、进入状态判断、冷却和去重。
- MiService 登录令牌的持久化和显式重新认证流程。
- 摄像头、检测器、规则及音箱动作的结构化、脱敏运行记录。
- Docker Compose 部署、健康检查和可重复的自动测试。

MVP 不包含：

- 指向斑马、大象、狮子等“手势 + 目标”组合识别。
- 动态插件发现、第三方插件安装或不重启热加载。
- 多摄像头并行检测、人物身份识别、人脸识别或人员跟踪。
- Home Assistant 运行时依赖；现有可选 PoC 路径继续保留。
- 用户、家庭成员、角色或登录系统。
- 截图、录像、音频文件或摄像头画面的持久化。
- 云端视觉检测和米家事件推送。
- 粤语播报、音乐播放或在管理页编辑欢迎语和检测阈值。

## 方案选择

采用单进程 Python 应用，go2rtc 继续作为独立容器运行。应用用一个 Uvicorn worker 同时承载
FastAPI 管理页、一个检测循环和一个播报消费者。

拒绝以下方案：

- 不把检测与 Web 拆为两个容器。MVP 没有独立扩缩容需求，拆分会增加消息传递、状态同步和
  排障范围。
- 不引入 Frigate 或 Home Assistant 作为事件中枢。当前直连路径已经通过现场验证，引入中枢
  会增加内存占用和新的故障边界。
- 不用多个 Uvicorn worker。每个 worker 都会重复加载模型并启动检测循环，既浪费 4 GB 内存，
  又会造成重复播报。

Python 不是领域上的硬性要求，但 MVP 延续现有 Python PoC，以复用已验证的 MiService 适配器、
FFmpeg 工具链和 OpenCV 生态，避免在设备验证之后再更换语言运行时。

## 模块与接口

新增长期运行代码放在 `src/daihougou/`；现有 `src/daihougou_poc/` 保持为兼容性探测工具。

### `vision.frame_source` 模块

接口向检测循环提供带单调时间戳的最新 BGR 帧。FFmpeg 适配器持续读取
`rtsp://127.0.0.1:8554/xiaobai`，使用 TCP RTSP，并在取帧阶段降至约 1 FPS。缩放时保持
原始宽高比，以中性灰补齐固定输入尺寸，避免把 16:9 人体压缩成正方形。它隐藏子进程启动、
帧边界解析、过期帧丢弃、stderr 限流、断线重连和无输出 watchdog。

只保留最新帧，不建立无界帧队列。检测速度慢于取帧速度时丢弃旧帧，确保规则看到的是当前
画面而不是积压画面。

### `vision.person_detector` 模块

接口接受一帧并返回最高人员置信度及检测耗时，不向调用者暴露模型输出张量。

首个适配器使用 `opencv-python-headless` 的 DNN CPU 后端，加载 OpenCV Zoo 的
`person_detection_mediapipe_2023mar.onnx` MPPersonDet 模型。输入帧先由 BGR 转为 RGB、
转换为浮点数并归一化到 `[-1, 1]`，再按比例缩放并用零补边到 224x224。模型返回 2254 个
候选框和对应 logit；MVP 只需要是否有人，因此对 logit 执行数值裁剪和 sigmoid 后取最高
置信度，不做边界框解码或 NMS。

模型 URL 固定到 OpenCV Zoo 提交 `47534e27c9851bb1128ccc0102f1145e27f23f98`，构建时校验
SHA384
`cdc21e3741c46ae24e4d2fa3c368886bd7dadcd23d98b6acdc0db966d2d9ecc5624c095fa05d5f949cce69ef1029f9ef`。
此前选择的 Open Model Zoo OpenVINO IR 模型需要 OpenCV wheel 未提供的 OpenVINO plugin，
不能由目标运行时加载；ONNX 模型直接使用 OpenCV DNN CPU 后端，不依赖 OpenVINO Runtime
或 AVX2。Intel HD Graphics 4000 不作为 MVP 推理设备；所有性能结论以目标 CPU 实测为准。

默认置信度阈值为 `0.55`，只能通过环境配置修改，不进入管理页。阈值与采样速率会在目标机器
现场校准，不能把开发机结果视为性能证明。

### `presence` 模块

这是一个不依赖摄像头、模型和时钟实现的纯状态机。接口接受观测时间和是否检测到人员，返回
零个或一个状态转换事件。

状态为 `unknown`、`absent` 和 `present`：

- 启动后先处于 `unknown`。首次稳定确认的状态只用于校准，不产生进入事件，避免应用重启时
  对已经在画面中的人误播欢迎语。
- 最近 3 次有效观测中至少 2 次有人时，确认 `present`。
- 从最后一次有效人员观测起连续 10 秒无人时，确认 `absent`。
- 只有 `absent -> present` 产生 `person_entered` 事件。
- 摄像头或检测器错误不是“无人”观测，不能推动离开状态。

状态机使用单调时钟计算时间间隔，避免系统时间校准导致错误转换。

### `rules` 模块

外部接口只接受领域事件并返回待执行动作。MVP 使用代码内注册表，不扫描文件系统，也不动态
导入模块。

`welcome_on_person_entry` 只处理 `person_entered`：

- 从代码内普通话欢迎语目录随机选择一句。
- 在 60 秒冷却期内不再产生动作。
- 规则关闭时不产生动作。
- 动作携带规则 ID；消费者执行前再次检查规则是否仍启用。这样关闭规则会取消尚未开始的排队
  动作，已经交给音箱的播报不尝试中断。

新增规则时实现同一内部接口、注册、测试并重新部署。这保留了清晰的替换位置，但不承担动态
插件机制的生命周期和安全成本。

### `speaker` 模块

接口保持 `speak(text) -> SpeakResult`，复用已经现场验证的 DirectSpeaker 行为。播报消费者在
单独的工作线程中串行执行阻塞式 MiService 子进程，视觉循环只负责把动作放入有界队列。

队列满时丢弃最新动作并记录失败，不阻塞检测循环。MVP 只有一条带冷却的欢迎规则，因此队列
容量设为 4 足够暴露异常积压而不会吞掉大量内存。

### `storage` 模块

使用 Python 标准库 `sqlite3`，不引入 ORM。模块隐藏建表、事务、并发锁和 JSON 编码，向上层
提供以下能力：

- 读取和原子更新规则开关。
- 记录脱敏事件。
- 查询管理页需要的最近状态和最后一次触发结果。

SQLite 数据库开启 WAL。数据结构至少包含：

- `rules(id PRIMARY KEY, enabled, updated_at)`。
- `events(id, occurred_at, kind, rule_id, success, latency_ms, details_json)`。

事件只存置信度、耗时、状态转换、结果码和分类后的错误，不存帧、摄像头 URL、账号、密码、
Token、DID、Cookie 或完整上游响应。启动时按事件数量清理，仅保留最近 5000 条。

### `runtime` 模块

该模块在 FastAPI lifespan 中构造并拥有帧源、检测器、状态机、规则引擎、存储和播报消费者。
它负责启动顺序、协作停止、健康快照和异常隔离。Web 路由不能直接操作 FFmpeg、模型或音箱。

关闭时先停止接收新帧，再停止规则分发，最后等待当前播报在有限时间内结束并终止 FFmpeg。

### `web` 模块

FastAPI 使用服务端模板和普通 HTML 表单输出唯一管理页：

- 应用、摄像头、检测器和音箱认证状态。
- `welcome_on_person_entry` 的名称、状态和最后一次触发结果。
- 一个开启或关闭规则的控件。

页面不提供配置编辑器、实时视频、功能介绍或用户管理。切换通过 POST 完成并重定向回首页。
状态修改验证同源 `Origin`/`Host`；应用只在配置的局域网地址监听，不配置公网暴露。

`GET /healthz` 返回进程、数据库和检测循环健康状态，供 Compose 健康检查使用。摄像头暂时断线
时页面仍可访问，`/healthz` 返回降级状态而不是让 Web 进程退出。

## 运行数据流

1. Compose 启动 go2rtc 和单 worker 应用。
2. 应用迁移 SQLite，加载模型，启动播报消费者，再启动 FFmpeg 帧源和检测循环。
3. 检测循环获取最新帧并在 CPU 执行人员检测。
4. 状态机将置信度转换为稳定的 `absent`/`present` 状态。
5. `absent -> present` 产生 `person_entered`。
6. 规则引擎读取当前开关和冷却状态，生成一条欢迎播报动作。
7. 播报消费者执行前再次检查开关，然后调用 MiService。
8. 各阶段只向 SQLite 写入脱敏元数据；管理页从存储和运行时健康快照读取状态。

## MiService 令牌生命周期

MiService CLI 把登录令牌保存在 `~/.mi.token`。PoC 当前用 `run --rm` 创建临时容器且没有持久化
用户主目录，因此每次容器删除后都会丢失令牌并重新要求验证码。

MVP 使用宿主机目录 `deploy/miservice/state/`：

- Compose 将其挂载到 probe 和应用的 `/var/lib/daihougou/mi`。
- 两个容器都设置 `HOME=/var/lib/daihougou/mi`，使 MiService 使用同一个
  `/var/lib/daihougou/mi/.mi.token`。
- 宿主机目录权限为 `0700`，Token 文件权限为 `0600`。
- 该目录同时加入 `.gitignore` 和 `.dockerignore`。

首次部署或令牌真正失效时，管理员通过带 TTY 的一次性 probe 命令完成 OTP。常驻应用不读取
stdin，不等待验证码，也不循环尝试登录。认证失效时，本次播报失败，运行状态变为
`reauth_required`，管理页提示需要重新认证。完成认证后无需重新构建镜像。

## 故障处理

- FFmpeg 意外退出：记录分类后的错误并按 1、2、4、8、16、30 秒上限重启。恢复成功后清零
  退避。重连期间不产生人员观测。
- 连续 30 秒没有有效帧：watchdog 终止并重建 FFmpeg，摄像头状态为 `degraded`，但 Web 和
  数据库继续运行。断流及推理失败会清除未完成的在场确认窗口，不能把无效间隔计入离开时间。
- 单次推理异常：记录错误并跳过该帧；连续异常使检测器状态为 `degraded`，不会被解释成无人。
- 检测循环或播报消费者意外退出：应用状态为 `unhealthy`，容器健康检查失败并由 Compose
  重启；可恢复的摄像头断线仍保持 `degraded`，不触发容器重启。
- SQLite 初始化或迁移失败：应用启动失败，让 Compose 重启，避免在无持久状态下继续运行。
- 播报超时或响应失败：记录一次动作失败，不自动重复播报，避免恢复后突然播放过期欢迎语。
- MiService 要求 OTP：标记 `reauth_required`，停止提交新的音箱子进程，直到 Token 文件更新或
  应用重启后重新检测。
- 播报队列已满：丢弃最新动作并记录 `speaker_queue_full`。

日志和事件不得包含摄像头源 URL、小米账号、密码、Token、Cookie、DID 或原始异常响应正文。

## 部署

Compose 增加常驻 `app` 服务，继续保留 `probe` tools profile 和可选 HA profile：

- `go2rtc` 使用 host network，API 和 RTSP 继续只监听回环地址。
- `app` 使用 host network，在显式配置的局域网地址和端口监听管理页；容器健康探针访问同一
  地址，不要求额外监听回环或所有网卡。
- `/var/lib/daihougou/data` 挂载到忽略的 `deploy/app/state/` 保存 SQLite。
- `/var/lib/daihougou/mi` 挂载到忽略的 `deploy/miservice/state/` 保存登录 Token。
- `app` 设置 `restart: unless-stopped`，并且只运行一个 Uvicorn worker。
- 模型文件构建进应用镜像，运行时不依赖临时下载。

应用配置使用独立的 `.env` 示例，不在镜像、Compose 或 Git 中写入真实凭据。管理页不得通过
路由器端口映射暴露到互联网。

## 测试策略

自动测试不依赖小米账号和物理设备：

- `presence` 表驱动测试覆盖启动校准、2/3 确认、10 秒离开、抖动、错误观测和单调时间。
- 规则测试覆盖关闭、冷却、随机语句来源和执行前二次开关检查。
- 帧源测试使用受控 FFmpeg 假进程覆盖最新帧、过期帧丢弃、EOF 和退避。
- 检测器测试使用固定、无隐私的许可测试图片，并验证模型输出解析；模型加载有独立烟雾测试。
- 存储测试覆盖迁移、开关原子更新、事件脱敏和 5000 条保留上限。
- Web 测试覆盖首页、开关 POST、同源验证和健康状态。
- 播报消费者使用假适配器覆盖成功、超时、队列满、关闭后丢弃及重新认证状态。
- Compose 静态测试覆盖单 worker、状态挂载、`HOME`、忽略目录和不得提交 Token。
- 容器集成测试使用生成视频验证“帧 -> 检测 -> 状态转换 -> 假播报”的完整链路。

物理设备验收：

1. 首次认证后连续重建两次 probe/app 容器，不再要求 OTP，并能完成一次测试播报。
2. 关闭规则，有人进入时不播报。
3. 开启规则并完成启动校准；画面无人至少 10 秒后有人进入，5 秒内听到一次欢迎语。
4. 人持续留在画面 2 分钟，不再重复播报。
5. 人离开至少 10 秒并等待 60 秒冷却结束，再次进入时听到第二次欢迎语。
6. 断开摄像头后页面显示降级且不误播；恢复摄像头后自动继续检测。
7. 确认 SQLite、日志和宿主机状态目录中没有保存任何画面。

开发完成不等于生产稳定。目标服务器上的 30 分钟功能运行可以作为 MVP 开发验收；此前尚未
执行的 8 小时摄像头、100 次音箱和资源压力测试仍需在扩大使用范围前完成。

## 后续演进

下一迭代可以新增“指向动物”规则，但应复用领域事件、规则动作和音箱接口，新增姿态/手势与
动物识别实现。动物名称是目录数据而不是写死一个斑马；新增斑马、大象或狮子不应修改规则
状态机。该能力不影响本 MVP 的数据结构和部署方式。
