# 大口九：场景变化物体播报规则设计

## 背景

大口九当前只有 `welcome_on_person_entry` 一条内置视觉规则。它持续以约 1 FPS 运行轻量人员
检测，在人员从画面外进入时通过摄像头配对音箱播报欢迎语。本次新增第二条内置规则，用固定
摄像头观察儿童绘本页面：启用后先分析当前画面，以后仅在画面明显变化时运行物体检测，并把
识别出的英文类别名直接播报。

领域词汇以仓库根目录 `CONTEXT.md` 为准。架构取舍见 `docs/adr/0001-*` 与
`docs/adr/0002-*`。

## 目标

1. 新增稳定规则 ID `announce_objects_on_scene_change`，与人员欢迎规则逐摄像头独立开关。
2. 首帧立即分析；以后以输入帧的 1 FPS 节奏执行低成本场景变化判断，静止时不运行物体模型。
3. 场景变化后不等待稳定、不设置固定推理抑制，立即运行一次物体检测。
4. 从固定 COCO 类别中排除人员和作为展示媒介的大幅书本，按置信度选最多三个不同类别。
5. 播报内容仅为英文类别名，例如 `cat, ball, dog`。
6. 保留现有人员模型，新增独立物体模型；两者共享一个串行且公平的 CPU 推理调度器。
7. 每台摄像头只保留一个 FFmpeg 解码源，并按启用规则选择帧尺寸。
8. 同一摄像头尚未开始的旧物体播报由新播报原位替换，等待超过 3 秒则丢弃。
9. 物体模型故障只降级物体规则，不中断人员欢迎、其他摄像头或管理页面。
10. 先通过目标硬件和真实绘本验证门禁，再扩展完整运行时与页面。

## 非目标

- 不做开放词汇检测、图像描述、OCR、故事朗读、实例身份、目标跟踪或数量变化。
- 不允许用户选择类别、修改英文标签、置信度、场景变化灵敏度或播报格式。
- 不把物体模型的 `person` 类用于人员欢迎规则。
- 不保存运行时截图、视频、检测框或模型原始输出。
- 不把临时验证图片提交 Git 或上传第三方。
- 不承诺识别 COCO 类别表之外的绘本对象，也不作为安全告警。

## 用户行为

管理页每台摄像头显示“人员进入欢迎”和“绘本物体播报”两个规则开关、各自运行状态和最近
结果。两条规则共用该摄像头现有的配对音箱。新摄像头和升级前已有摄像头的物体规则均默认
关闭；升级不改变欢迎规则、音箱配对或历史事件。

物体规则开启或摄像头恢复后的第一帧必定进入物体检测。以后每个输入帧先经过场景变化判断：

```text
1 FPS 最新帧
    |
    +-- 人员规则开启 ----------------------> 人员检测 -> 人员状态机 -> 欢迎规则
    |
    +-- 物体规则开启 -> 场景变化判断
                            |
                            +-- 未变化 -> 跳过
                            +-- 已变化 -> 物体检测 -> 类别筛选 -> 物体播报规则
```

不同页面出现相同类别时仍会再次播报。同一画面内同类别的多个实例只保留一个类别。没有可靠
支持类别时保持安静，不播报 `unknown`，也不写普通“无结果”事件。

## 支持类别

物体模型使用 COCO 80 类英文顺序作为稳定类别表。`person` 从可播报列表中永久排除。其余
类别均为支持类别，并在设置页以只读中英文表显示。首版不为摄像头配置类别子集。

常见但不支持的绘本对象包括狮子、老虎、兔子、猴子、狐狸、猪、恐龙和鱼。页面必须明确说明
“仅支持列表中的类别”，不能使用“任意物体”或“所有绘本对象”等文案。

`book` 有一条例外：检测框面积达到原始画面面积的 50% 时，视为承载插画的物理绘本并排除；
小于该比例的书本插画仍可播报。50% 是 PoC 候选值，只有在验证报告记录新值和依据后才能调整。

## 场景变化判断

每台开启物体规则的摄像头拥有独立 `SceneChangeGate`。候选算法如下：

1. 把 BGR 帧缩小到 `64x64` 并转换为灰度。
2. 第一帧保存为参考帧并返回“已变化”。
3. 后续帧与上一采样帧执行绝对差。
4. 像素绝对差至少为 `25` 时视为变化像素。
5. 变化像素达到总像素的 `20%` 时返回“已变化”。
6. 无论结果如何，每次都用当前灰度帧替换参考帧。

候选常量为 `SCENE_PIXEL_DELTA = 25`、`SCENE_CHANGED_RATIO = 0.20`。小幅噪声和曝光变化应
低于门槛。一次翻页可能让连续采样帧都进入物体检测，这是已接受的行为；系统依靠待播报覆盖
而不是稳定等待或固定冷却处理它。

## 物体检测

PoC 候选模型为 OpenCV Zoo `Nanodet-m-plus-1.5x_416` FP32 ONNX：

- 固定提交：`47534e27c9851bb1128ccc0102f1145e27f23f98`
- URL：`https://media.githubusercontent.com/media/opencv/opencv_zoo/47534e27c9851bb1128ccc0102f1145e27f23f98/models/object_detection_nanodet/object_detection_nanodet_2022nov.onnx`
- 文件大小：`3800954` 字节
- SHA384：`84ee6a6dd605f7019f25a81615a8fff886b235e8d3924930ca367c6e239a8c6d9c14a7e60b8bae54edca040cbf7b86e7`
- 许可：Apache-2.0
- 输入：保持宽高比并填充到 `416x416` RGB
- 置信度候选值：`0.35`
- NMS IoU 候选值：`0.60`

`ObjectDetector.detect(frame)` 返回原始画面坐标中的不可变检测集合和推理耗时。领域规则负责
排除 `person`、大幅 `book`，按类别取最高置信度、降序排序并截取前三类。检测框只用于内部
筛选，不进入事件、页面或日志。

## PoC 门禁

验证语料是目标服务器本地临时目录，包含 `manifest.json` 和无人物的绘本页面。格式固定为：

```json
{
  "pages": [
    {
      "file": "page-001.jpg",
      "primary": "cat",
      "expected": ["cat", "book"]
    },
    {
      "file": "unsupported-001.jpg",
      "primary": null,
      "expected": []
    }
  ]
}
```

`primary` 是该页应优先识别的一个支持类别；`expected` 是该页所有允许播报的支持类别。验证
至少包含 30 页，其中至少 20 页有 `primary`，并覆盖单物体、多物体、重复类别、不同光线和
不支持类别页面。脚本不写结果图片，只输出 JSON 汇总。

通过条件：

- `primary` 命中率至少 80%；
- 存在预测类别不属于 `expected` 的页面比例低于 5%；
- 目标 i3-3217U 上物体推理耗时 p95 不超过 1000 ms；
- 两路摄像头等效负载下，人员与物体模型同进程峰值 RSS 不超过 1 GiB；
- 两路每秒人员任务加变化触发物体任务的总 p95 周期不超过 1000 ms，不产生跨周期积压。

PoC 不通过时立即停止生产功能扩展，回到模型或类别范围决策。通过后把汇总写入
`docs/validation/object-category-announcement-poc.md`，删除临时语料，只保留指标和硬件信息。

## 推理调度

共享调度器按检测器类型管理独立工厂和实例：`person` 与 `object` 分别加载、释放和报告状态。
第一台依赖某类型的摄像头启用时加载对应模型，最后一台关闭时释放。加载或推理失败只清理并
降级同类型检测器；另一个类型和调度消费任务继续工作。关闭后重新开启或应用重启才会重试。

作业键为 `(detector_kind, camera_id)`。每个键最多一个未完成作业；消费者按入队顺序串行调用
模型，摄像头协程只能在上一个作业完成后提交同键新作业，因此不会形成无界积压。不同摄像头
和检测类型没有绝对优先级。帧源只保留最新帧，推理慢时自然跳过旧帧。

## 摄像头运行单元

每个运行单元根据持久化规则集合决定需要的管线。两条规则同时开启时，并发提交人员和物体
作业，由共享调度器串行执行，完成后分别处理结果；一个结果失败不取消另一个。

只开启人员规则时，FFmpeg 输出 `256x256`。开启物体规则时，同一个 FFmpeg 源输出
`416x416`，人员模型从该帧自行缩放到 `224x224`。规则集合变化导致尺寸变化时允许停止并重建
该摄像头运行单元；不启动第二路 FFmpeg。

摄像头无帧时，两条规则状态失效但不制造离开或场景变化事件。摄像头恢复后的首帧重新触发
物体检测；人员状态仍从未知开始校准。

## 物体规则与动作

`ObjectCategoryAnnouncementRule` 消费一次 `ObjectDetection` 并返回 `SpeechAction | None`。
动作文本是最多三个英文标签使用 `", "` 连接的结果。动作携带：

- `camera_id`、`rule_id`、`speaker_id`、创建单调时间；
- 结构化 `objects`：每项仅含 `label` 与四位小数置信度；
- `coalesce_key = (camera_id, rule_id)`；
- `max_queue_age_seconds = 3.0`；
- 完成事件名 `object_announcement_completed`；
- 覆盖事件名 `object_announcement_superseded`。

## 音箱队列

每个音箱仍只有一个消费者，不同音箱可以并行。队列按创建顺序保存欢迎动作和物体动作。提交
带 `coalesce_key` 的物体动作时，如果同队列存在尚未开始且键相同的动作，新动作在原位置替换
旧动作，并为旧动作记录 `object_announcement_superseded`。欢迎动作不覆盖。

真正播放前检查：

1. 等待时间没有超过 3 秒；
2. 对应规则仍开启；
3. 摄像头仍配对动作中的音箱。

失败时分别记录 `speaker_skipped_expired`、`speaker_skipped_disabled` 或
`speaker_skipped_pairing_changed`。开始播放后不取消。物体播报成功或音箱调用失败都使用
`object_announcement_completed` 一条事件，`success` 区分结果，详情保存类别、置信度和脱敏
结果码。

## 存储与升级

SQLite schema v2 已用 `(camera_id, rule_id)` 作为规则主键，不需要修改表结构或
`PRAGMA user_version`。初始化时为所有已有摄像头 `INSERT OR IGNORE` 一条关闭的物体规则；发现
新摄像头时同时创建两条关闭规则。这个数据补齐必须幂等，并保留现有全部值。

事件仍使用现有 `details_json`，不增加列。模型路径、检测框、页面图像和原始网络输出均不得
写入数据库。

## 页面与接口

`POST /commands/camera-rule` 增加必填 `rule_id`，只接受两个内置规则 ID。异步 JSON 响应返回
该摄像头完整规则状态。未知摄像头返回 404，未知规则返回 400，继续执行现有 Origin 与 CSRF
校验。

首页每个摄像头行显示两个紧凑规则控制块，不使用嵌套卡片。每条规则包含名称、开关、状态和
最近结果。摄像头流状态和音箱选择仍只显示一次。设置页在欢迎词编辑器后增加只读中英文支持
类别表，不增加物体规则表单。

健康接口分别返回 `person` 与 `object` 检测器状态。没有启用依赖规则时 `stopped` 属于正常；
某检测器只有在至少一台摄像头启用对应规则且其状态为 `degraded` 时才让整体状态降级。人员
检测器、物体检测器和音箱管理器必须分别报告故障。

## 发布与运维

生产镜像从固定 URL 下载两个模型并分别执行 SHA384 校验。仓库增加 NanoDet Apache-2.0
第三方许可文本。环境新增 `OBJECT_MODEL`，默认
`/opt/daihougou/models/object_detection_nanodet_2022nov.onnx`；不增加面向用户的物体阈值环境
变量。

首次加载状态、故障隔离和真实绘本效果限制。运行时不得下载模型或访问视觉云服务。
